# Single-target skill miss completion

At 02:42:04 UTC on September 12, AresTempest's Stab 5 (skill 274) missed Alpha Demon on Wonderland island 1. Its final server line reports hit roll 9837 against a 9800 chance, mana 3141, and successful caster notification. Subsequent monster attacks and player recovery continued, while the user reported that neither movement nor skills worked. The character had entered with no status controls; Wonderland's first island has no stun or silence application.

The shared Legacy/ECS miss publisher sent native cast start 10040 and mana, then returned without an impact-completion message. All its awaited work had finished before the recorded log. The installed client enters action state 7 on cast start. Its normal completion packet, 10046, advances that state to 8, starts the skill effect and closes the casting bar. A missed attack still needs that completion phase.

A managed stack sample completed in under one second and found no blocked handler or registry monitor. Attacks, recovery, readiness probes and an established game socket continued; socket queues were empty. This differs from the previous registry/vitals deadlock, whose blocked monitor chain also stopped those loops. Suspended asynchronous waits are a limitation of the stack tool, so this does not prove the absence of every possible wait. Current Origin connects directly to Tempest, bypassing the external packet proxy; that proxy's capture file contains only older traffic. Windows denied read-only access to the live client actor. The missing completion and native consequences are proven by source and executable inspection; the exact live actor state was not observable.

The fix completes accepted single-target misses with 10046 for the caster and the monster's existing viewers. Caster completion is independent of whether the target remains visible: an already-started local cast must finish even when the target disappears. Completion uses finite server positions. Intoned casts retain their original start and receive only their completion when resolution runs. Mana, cooldown, hit chance, monster health and reward rules stay the same.

No damage packet is needed for a miss. In particular, the native 10045 branch can interpret damage `FFFFFFFF` as negative damage and add one point of client health; it is not a neutral miss sentinel for this packet format. The fix therefore sends the normal effect-completion packet without fabricating a health change or interrupting an accepted cast.

The regression exercises actual handler dispatch, encrypted packet output, deterministic missed Stab and intoned Thunder in both player runtimes, unchanged target health/revision, one mana charge per cast, and subsequent movement. Its expected native sequence is start 10040, completion 10046, then mana 10135, without a 10045 damage/healing frame.

Validation: the regression failed on the old publisher when a real Stab miss produced mana where terminal 10046 was required (`protocol-red-fixture.json`). With the fix, both player runtimes complete Stab, persist the following move, and complete the next intoned Thunder. Monster health and its revision remain unchanged; mana moves 500 to 260 to 200 with exactly two vitals writes. The setup finds deterministic miss rolls through real target health revisions and the current resolver rather than assuming a particular hit-rate formula. No synthetic hit result is injected.

The final Release build passed with zero warnings or errors. All 31 focused checks passed, with no failures, skips or unmatched filters. Coverage includes the new missed-cast regression, the existing intoned lifecycle, Wonderland encounters/statuses/transporters/completion/rewards, and the previous lock-order regressions. An initial test setup assumed the wrong accuracy formula, and a later assertion incorrectly expected the player's own movement echo; both test-only assumptions were corrected before the final pass. Tests now assert the actual persisted movement, consistent with the normal native movement path.
