# 仙境（Wonderland）计分与接线修复 — 20260928

## 一、问题结论：为什么"杀怪没有计分"

仙境的一切进度只有一个来源：**提交后的击杀**。

```
玩家攻击/技能/范围/持续伤害
  → GameSessionRegistry.TryCommitPlayerMonsterDamageGuarded / TryApplyPveElementalMonsterDamage
  → MapInstance.CommitUnboundPlayerDamageLocked（地图 207 没有 Medusa owner，走"未绑定"分支）
  → WonderlandMonsterRuntime.TryApplyDamage（这里已经做了战斗窗口、友军免伤、末位宝箱守卫锁定）
```

而负责计分的方法 `GameSessionRegistry.WonderlandCombat.Commits.cs:ObserveWonderlandMonsterDamageCommitted`
→ `GameSessionRegistry.WonderlandRun.cs:RecordWonderlandMonsterKillCommitted`
→ `MapInstance.Wonderland.cs:RecordCommittedWonderlandKill`
→ `WonderlandRunRuntime.RecordCommittedKill`（清完一岛的必需怪 → `CompletedIslands + 1`）

**只有** `TryApplyWonderlandMonsterDamage` 一个调用者，而那个方法全仓库零调用（写好了从来没接上）。
所以提交伤害这条路永远不产出击杀事件 → `CompletedIslands` 永远 0。

连锁后果（全部是同一个根因）：

| 现象 | 机理 |
|---|---|
| 杀怪不计分 | 击杀事件没产生 |
| 传送 NPC 永远说"未解锁" | `TryResolveWonderlandTravel` 条件是 `run.CompletedIslands >= 当前岛`（这就是"分数"） |
| 黑市传送只能跳回第 1 岛 | 目标岛 = `Math.Min(8, CompletedIslands + 1)` |
| 面板分数不动 | 面板分数就是 `CompletedIslands`（`RepetitionFightInfo`，`GameSessionRegistry.WonderlandUi.cs`） |
| 宝箱点不开 | 宝箱要 `_wonderlandTitleSettled`，而它由岛屿通关（`QueueWonderlandTitleMilestone`）产生 |
| 8 岛终点 NPC 不放行 | `TryResolveWonderlandFinalExit` 要 `_wonderlandTitleSettled[8]` |

## 二、本次接线清单（每条都对应一个"零调用"成员）

### 1. 计分（核心）
- `GameSessionRegistry.MedusaPlayerDamage.cs`：`TryCommitPlayerMonsterDamageGuarded` 提交成功后调用
  `ObserveWonderlandMonsterDamageCommitted(runtime, commit.DamageResult, committedAt, context)`。
  这是普通攻击、技能、范围技能、烈焰爆破、ECS 攻击**共同**的唯一提交点。
- `GameSessionRegistry.ElementalCombat.Transactions.cs`：持续伤害（元素 DOT）打死 BOSS 也计分。
- 观察器自带时间闸门（`TryResolveWonderlandDamageTimeLocked`）与生命版本去重（`state.DamageRevisions`），
  非 207 地图立即返回，其它副本不受影响。
- 友军（`IsAllied`）与未公布怪物不会计分：这条规则原本就在 `WonderlandRunRuntime` 里。

### 2. 三个存储从未注入（NPC 全部不可用的第二根因）
`ConfigureWonderlandChests` / `ConfigureWonderlandBlackmarket` / `ConfigureWonderlandTitles` 三个方法
全仓库零调用 → `_wonderlandChests` 永远是 null → 宝箱与 BOSS 尸体领取永远返回 `Unavailable`。

- `Infrastructure/PostgresApplicationDataRuntime.cs`：构造并暴露
  `WonderlandTitles` / `WonderlandChests` / `WonderlandBlackmarket`（表已存在：
  `wonderland_title_runs/milestones/members/character_title_ownership`、`wonderland_chest_claims`、
  `wonderland_boss_loot_claims`， sacks 物品 4450–4461 已发布 12 条）。
- `GameClientHandlerFactory.cs`：按 Atlantis/Medusa 同样方式在 `Create` 里注入，
  `ConfigureWonderlandTitles(store, LegacyInstanceDailyEntries)`。

### 3. BOSS 尸体掉落
- `GameSessionRegistry.WonderlandBossLoot.Presentation.cs:PublishPendingWonderlandBossLootAsync` 零调用
  → 尸体掉落窗口从不下发。现由 `GameSessionRegistry.MonsterWorld.cs` 的世界 tick 每帧发布
  （失败只记日志，不让 roaming 循环 fault）。
- `GameClientHandler.WonderlandBossLoot.cs:TryHandleWonderlandNativeLootPickupAsync` 零调用
  → 客户端点 BOSS 尸体（C2S **10050，20 字节**）不会走仙境领取。已在 `GameClientHandler.Dispatch.cs`
  的 10050 分支里排在通用地面掉落（16 字节）之前。
- `ClearExpiredWonderlandCorpseLootAsync` 零调用 → 尸体移除前不清理本地掉落状态。
  已在 `SendMonsterRuntimeTickAsync` 发送 `RemoveWorldObjects` 之前调用（非 207/非 BOSS 尸体立即返回）。

### 4. BOSS 机制（命中的减益/增益）
- `CommitWonderlandIncomingEffectsLocked` 零调用 → 眩晕/沉默/破甲/圣鸟祝福永远不会落到玩家身上
  （`GetWonderlandPlayerControl` 的**读取**侧本来就在技能施法里生效，所以只会"永远不晕"）。
  已在 `GameSessionRegistry.MonsterAttacksEcs.Transaction.cs` 的"攻击已不可逆提交"分支里调用，
  与元素收尾同一位置；效果立即进入 `_wonderlandStatusSessions`。
- 这次调用同时激活了它内部的 `QueueWonderlandNativeAreaLocked`（原样零调用）→ 捕获的"原生范围伤害"
  批次真正开始工作。
- `AdjustWonderlandPlayerModifiers` 零调用 → 圣鸟/腐鸟祝福不加命中与攻击。
  已在 `GameSessionRegistry.MountStatus.cs:GetRuntimeStatusAggregate` 出口统一叠加：这是所有
  普攻、技能、UI 状态帧读取聚合属性的唯一入口。
- `MergeWonderlandStatusOverlay` 零调用 → 减益图标不显示。已在
  `GameSessionRegistry.TrainingDummyHostileStatusPublishing.cs:MergeTrainingDummyClientStatusOverlays`
  末尾合并。

## 三、验证方法（无需测试工程）

1. 部署：`dotnet publish src/Godswar.Server/Godswar.Server.csproj -c Release`
   → `docker compose --profile legacy-raw build server`
   → `docker compose --profile legacy-raw up -d --force-recreate server`
   （抓包代理会占用 7000/5998，部署前先停）。
2. 进副本打怪，看服务器日志：
   ```
   docker logs -f godswar-server | Select-String wonderland
   ```
   期望：清完一岛必需怪 → 出现 `[wonderland] score ... island=1 cleared=1`。
3. 第三关宠鸟祝福：被"伪装宠物鸟"命中后应出现
   `[wonderland] petbird blessing … physical-and-magic-attack=5x seconds=15`；
   随后 15 秒内的普攻与技能伤害应为原来的约 5 倍（物理与魔法都吃）。
4. 客户端面板：`RepetitionFightInfo` 的进度数随清岛增加。
5. 传送 NPC：清完 1 岛后点 1 岛传送 NPC 才能进 2 岛（未清岛时应收到 `[0, 99+island]` 的拒绝回应）。
6. 黑市 NPC：购买后应被送到 `CompletedIslands + 1` 岛；银币不足返回 141。
7. 宝箱：清岛 → 标题结算（`[wonderland] title settlement will retry ...` 若出现即为失败，需要看原因）
   → 宝箱可开；8 岛终点 NPC 在 8 岛结算后才放行。
8. BOSS 尸体：击杀后本地应出现掉落窗口，点尸体（10050）应进包，日志
   `[wonderland-loot] character=... boss=... sack=... status=Claimed`。
9. 死亡：应弹出复活窗（原生 10027），复活后回到本岛入口，日志 `[wonderland] free revive ...`。
10. 若怪物打不动人/不还手，先看
    `[wonderland] incoming attack rejected …`（第二轮接入的准入闸门）与
    `[monster] ECS attack rejected …`；若 BOSS 伤害过强或过弱，回退点是
    `ResolveWonderlandMonsterAttack` 与 `AdjustWonderlandMonsterTarget` 两处调用（改回
    `MonsterIncomingCombatPolicy.ResolveAttack`／移除串联即可）。

## 三之二、第二轮接线（宠鸟祝福 ×5 与捕获战斗数值）

### 1. 宠鸟祝福"物理魔法攻击五倍"没有生效（第三关）

`ClientStatusAggregate.AttackMultiplier` 这个字段**全仓库只有写入点、没有读取点**：

- 写入：`GameSessionRegistry.WonderlandCombat.State.cs:AdjustWonderlandPlayerModifiers`
  （`effects.AttackUntil > now ? 5 : …`，由 `CommitWonderlandIncomingEffectsLocked` 在"伪装宠物鸟"命中时设置 15 秒）。
- 读取：**没有**。所以祝福图标会出现、命中加成（腐鸟 +25000 Hit）会生效，唯独 ×5 攻击完全无效。

已接上的读取点（覆盖全部输出伤害路径）：

| 位置 | 覆盖 |
|---|---|
| `World/Systems/Combat/CombatCharacterStatsAdapter.cs:ApplyRuntimeAttackerModifiers` | 传统普攻 `MonsterCombatResolver`、技能 `SkillCombatResolver`、烈焰爆破 `CapturedFlameBlastV3`、试炼假人、PvP |
| `Game/PlayerCombatEcsAdapter.State.cs:SnapshotOffense` | **生产路径**：ECS 普攻/技能/范围（`ResolvePlayerCombatEcs` → 每次出手都用当前聚合刷新） |

两处都对 **PhysicalAttack 与 MagicAttack 同时**乘以倍率（`SaturatingMultiply`，倍率 ≤1 时原样返回，
所以其它任何状态都不受影响）。

附带修掉一个会让祝福"偶尔完全不生效"的坑：`GameSessionRegistry.MountStatus.cs:GetRuntimeStatusAggregate`
在没有该玩家的状态状态机时会提前返回 `ClientStatusAggregate.Empty`——仙境祝福不是运行状态，
现在这条提前返回也会叠加仙境层。

运维可见性：祝福首次生效会打印一行（窗口内刷新不刷屏）：
```
[wonderland] petbird blessing character=<名字> physical-and-magic-attack=5x seconds=15
[wonderland] putridbird blessing character=<名字> hit=+25000 seconds=15
```

### 2. 捕获到的怪物攻防数值（原先三处零调用，现已接线）

| 位置 | 接线方式 |
|---|---|
| `WonderlandCombat.Resolution.cs:AdjustWonderlandMonsterTarget` | 并入唯一入口 `GameSessionRegistry.ElementalCombat.MonsterAdjustments.cs:AdjustPveMonsterTargetStats`（4 个调用点全部覆盖）：BOSS 等级/双防/闪避、derskey 物理减伤 80%、monkeyface 魔法减伤 80%、multihead 直取命中率 |
| `WonderlandCombat.Resolution.cs:AdjustWonderlandMonsterProfile` | 并入 `AdjustPveMonsterAttackerProfile`：怪物使用计划表的等级/攻击/通道/射程/BOSS 标记，之后再由 `WonderlandCapturedAttackPolicy.ApplyProfile` 用捕获伤害反推有效攻击（两者的顺序就是设计顺序：计划值作为上界） |
| `WonderlandCombat.Resolution.cs:ResolveWonderlandMonsterAttack` | 替换两处实时解算：ECS 事务 `MonsterAttacksEcs.Transaction.cs` 与旧路径 `MonsterAttacks.cs`。BOSS 技能改用捕获的 `ResolveSkillDamage`（含技能倍率）、破甲后按 `ArmorPenaltyBasisPoints` 削减玩家防御、地火魔法攻击 22000、反弹伤害直通 |
| `WonderlandCombat.Resolution.cs:IsWonderlandIncomingAttackAllowedLocked` | 放在 ECS 事务取到目标之后、解算之前：施法被打断、岛屿未公布、怪物身份过期、原生范围打击已离开半径、友军攻击玩家——一律拒绝并打印 `[wonderland] incoming attack rejected …` |

注意两者都按地图自守护：非 207 立即返回原值/`true`，其它副本行为不变。
第三关 BOSS（FlameRooster）的数值仍按既有要求保留（`ApplyProfile` 对该角色直接返回原值）。
