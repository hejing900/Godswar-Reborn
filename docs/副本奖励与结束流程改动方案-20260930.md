> 依据：运营提供的三张奖励表（高级/普通美杜莎、亚特兰蒂斯）与本轮定位出的两个 BUG。
> 本文只描述**将要改什么**，不含代码改动。

> 每次进入副本独立结算（`world_instance_id` 幂等）。

| 副本 | 奖励表现状 | 需要做的接入 | 结算入口（已定位） |
|---|---|---|---|
| **美杜莎** | **表已存在且与运营表格逐档一致**：`MedusaIslandPolicy.cs` 普通版未完成 `(0,300)…(2200,750)`、完成 `40→975…10→1350`；高级版完成 `40→1800…10→2250`；称谓档 `Title(...)` 仅高级版 | **不动表**，只把"手动结束 / 时限到期"接进结算（现在只在通关时结算） | `GameSessionRegistry.MedusaCompletionEgress.cs` → `SettleMedusaCompletionRewardAsync`（现有幂等键 `_medusaCompletionRewardSettled`） |
| **亚特兰蒂斯** | **只有完成档**（850 → 2800 + 称谓；称号按人数：1 人深海狩猎者 / 2+ 海底探索者）。**未完成 13 档不存在** | ① 按运营数据**新建 13 档未完成表**；② **新增一条数据库迁移**放宽三条硬约束（`final_score = 850`、`hard_points = 2800`、`honor_after - honor_before = 2800`）；③ 契约放宽（分数 0–850、称号可空）；④ 修订号升版；⑤ 接入三种终态 | `GameSessionRegistry.AtlantisCompletionRewards.cs` → `SettleAtlantisCompletionRewardsAsync`（现在只在 point850 通关时冻结证据） |
| **飘渺** | 称号是**按岛屿逐个结算**（里程碑制），已满足"按进度" | 不改规则；只需确认：**手动结束/到期时已获得的称号不被回收**，未清完的岛不发；另外**修掉我引入的称号重试回归**（请求与回执两侧名单不一致 → 每 tick 重试） | `GameSessionRegistry.WonderlandRun.cs:209-221` → `WonderlandTitleRequest`；回执校验在 `PostgresWonderlandTitleStore` |

飘渺只需修回归 + 验证，港湾无需改动。

## 三、验证方式

1. **奖励表逐档断言**（新增/改写检查）：
   - 亚特兰蒂斯：14 个积分档（含 0 与 850）→ 徽记与称号（1 人 / 2 人以上两种）；
   - 美杜莎：普通版与高级版 × (未完成 7 档 + 完成 6 个用时档) → 荣誉，高级版 20/15/10 分钟的称谓；
   - 既有的"完成态"用例必须仍然通过（不能因为放宽契约而让满分场景数字变化）。
2. **结束流程**：三副本各跑一次"手动结束" → 断言四帧顺序、30 秒倒计时、到期自动回城、点击立即回城。
3. **队长转交**：构造队长掉线 → 断言继任者产生、面板刷新、继任者能结束副本。
4. **回归**：全量协议检查与改造前对比**无新增失败**（当前基线 456 通过 / 22 失败）；飘渺称号重试风暴消失。

## 四、需要你确认的四个细节

1. **积分取档规则**：未完成档是否按"**不超过当前积分的最大档**"取？（例：积分 900 → 亚特兰蒂斯取 80 档的 900 徽记；美杜莎取 0 档的 300/600）我按这个实现，若规则不同请指出。
2. **美杜莎"完成"的判定**：表格写的是"获得 3000 团队积分完成副本"，是否**只看积分达到 3000**（用时只决定档位）？还是要同时满足时限内？
3. **用时怎么算**：从**副本创建/队长进场**开始算，到达到 3000 分（或手动结束）为止？我用"运行开始 → 终态"。
4. **队长转交顺序**：按"**进入副本的先后**"（最早进入者接任）可以吗？还是按其他顺序（等级/职业/角色 ID）？

确认后我按顺序施工：**D（解互锁）→ C（队长转交）→ B（结束走完成态 + 30 秒）→ A（按进度发奖，含飘渺回归）**，每一段单独构建 + 跑全量对比 + 部署验证。
