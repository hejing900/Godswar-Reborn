之后客户端点某个页号就回 `C2S 10069 {npc, 16, 16, ...}`（页号在 +8/+12 各一份）。

## 3. 消息 id（= 脚本的 SubID）含义，来自客户端脚本与文案

`NpcFunLuckyGods.lua`：`Index==1` 时 `SubID` 100/101/1000/1001/104；否则 `SubID==201`、
`SubID%10==2/6/7/8/9`、`SubID%100==3/4/5`。

| SubID | 客户端行为 |
| --- | --- |
| 100 | 显示说明 `NF_L0_L001` + 按钮"选择波塞冬"(`L002`) |
| 101 | 按钮"选择阿波罗"(`L003`) |
| 1000 | 按钮"领取奖励"(`L007`) |
| 1001 | "必须达到55级以上才可以许愿"(`L012`) + 结束 |
| 104 | "今天的许愿次数已经用完"(`L013`) + 结束 |
| 201 | "很抱歉，你暂时还没有任何奖励"(`L016`) + 结束 |
| x2 (如 2、102) | 连续 7 次命中：`L022` + 经验 + `L023` |
| x3 | "你没有进行任何选择"(`L005`) + 结束 |
| x4 / x5 | 显示按钮"选择阿波罗"(`L003`) / "领取奖励"(`L007`) |
| x6 | "5分钟才能选一次！请再过 N 分钟"(`L017`+N+`L018`) |
| x7 | "见好就收…你今天还能许愿 N 次"(`L011`+N+`L015`) |
| x8 | "运气不好，你选择错误。你今天还能许愿 N 次"(`L008`+N+`L015`) |
| x9 | "恭喜！你将获得 N 经验"(`L004`+N+`L014`) + 按钮"选择波塞冬" |

规则（文案原文）：55 级才能许愿；**每 5 分钟 1 次、每天 10 次**；向波塞冬/阿波罗之一许愿，
选对给经验；**连续选对奖励翻倍**，选错则本轮奖励清零；连中 7 次直接给奖励并结束；
奖励必须当天领取。

## 4. 我们服务端的现状与差距

- 许愿池在我们服务端被当成**纯描述 NPC**处理（`GameClientHandler.NpcDialogOpen.cs:169`
  明确写了"the Wishing Pool is one"），点它只会弹说明，**没有任何功能菜单**。
- 要做这个功能需要：
  1. 对话框应答改成 `flags 0x200 + packed [16,24,50] + 脚本名 Athens_074/Sparta_074`；
  2. 实现 10069→10070 的状态机：页 16 = 许愿（选神）、页 24 = ?、页 50 = 等级/说明页；
  3. 服务端状态：等级门槛、5 分钟冷却、每日 10 次、连中计数与翻倍、待领奖励（当天有效）；
  4. 奖励发放（经验）与"领取"分支。

## 5. 还没抓到、需要补的东西

- **一次真正的许愿**：本轮全部落在"没有奖励/等级不够/菜单页"分支上，
  所以"选神 → 结果(对/错) → 经验数字 → 领取"这几帧还没样本，
  翻倍与连中 7 次的真实数值也无法确认。
- 页 24 与页 50 的确切用途（16 明显是许愿页；24/50 从应答看分别是另一组菜单与说明页）。
- 消息 id `601` 在 `NpcFunLuckyGods.lua` 里没有对应分支，需要更多样本或其它脚本确认。
- 10038（每秒一条 "Avenging Wrath"/"1232#"、"Orig01"/"1233#"）与许愿池**无关**，
  是登录后对其它在线玩家的周期性服务器提示，实现许愿池时可忽略。
