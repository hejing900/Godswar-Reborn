## 2. 规则与公式（全部可指向客户端原文）

### 2.1 技能书分类

- 客户端 `ItemBaseAttribute.xml` 带 `PetSkill=` 的 **402 行**，其中 12 行完全重复
  （`10600-10605`、`10610-10615`）→ **390 个唯一道具**，归入 **68 个家族**。
- **24 个通用家族 / 126 本**（`Message_Pet.dat` 的 `PetInfo<技能ID>` 没有种族字样）。
- **44 个种族专属家族 / 264 本**，客户端有两种写法，**都必须匹配**：
  - `仅X可学`（家族 1、2、11、41、42、51、61、62、81、101、261、321、341、370、381、382、400-420）
  - `X的特有技能`（家族 **421-427**，早期只扫第一种写法会漏掉这 7 个家族）
- 种族名 → 种族 ID 用 `UI/Base/text.lua` 的 `PETTYPE<n>`，44 个名字 100% 落在种族 1-44。
- 学习判定：`通用 OR 书的专属种族 == 宠物当前 species_id OR 书的家族 == 宠物天生技能家族`。
  最后一条是**天生家族豁免**（种族 45 丘比特天生带小刺猬家族 427，必须能升级它）。
- 换皮（魔晶改种族）后按**当前** species_id 判定；已学家族不受影响。
- 等级 I→VI 必须逐级学，且满足 `Trait`（悟性/准确等）门槛。

### 2.2 技能效果

- `Effect`（= `Genre`，1661 行全部相等）决定属性通道；`Add=1` 给主人、`Add=2` 给宠物自身。
- 数值取自 `Values[]`，阶段由 `Restrict[]`（宠物 rank 阈值）决定：
  取 **≤ 当前 rank 的最高一档**，是**绝对值不是叠层**。
- 例：黑暗逆袭 `Restrict="0,8,19" Values="40,75,100"`
  → rank 0-7 = **40 魔法攻击**、rank 8-18 = **75**、rank ≥19 = **100**。
- **百分比类效果在人物属性表里是万分比**（×10000）：effect `19,20,21,22,25,37`。
- **effect 34 一族两义**：家族 `340/341/426` 是"每次有效攻击固定回血"（`life_absorption_flat`），
  只有作者新增的家族 `428`（吸血/Vampiric）是百分比（`life_absorption`，×10000）。
- **只对出战宠物生效**（`pet.is_summoned`），携带但召回 = 不生效。
- 效果 `43-48`（家族 430-480 六族"符记"）是加在**宠物自身**资质上的，
  **不在本投影里**；运营方确认该链路已有效，本轮未改、未重复取证。

### 2.3 照护三属性

| 规则 | 值 | 依据 |
|---|---|---|
| 饱食度上限/下限 | 100 / 0 | 用户要求 + `character_pets` 约束 |
| 好感度上限/下限 | 100 / 0 | 同上 |
| 寿命上限/下限 | 1500 / 0 | 同上 |
| **扣减条件** | **出战且未合体** | 用户明确纠正：合体期间不掉 |
| 饱食度 | 每 **10 分钟** −2 | 用户指定（客户端无速率配置） |
| 寿命 | 每 **10 分钟** −2 | 同上 |
| 合体 | **瞬间** −40 好感 | 用户指定 |
| 低于 40 好感不能合体 | 40 | `PetManagerPlanner.MinimumOwnerMergeAmity`（原有） |
| 饱食=0 或 寿命=0 | 不能出战 | 用户指定 |

**客户端没有扣减速率配置**（已全量搜索 `zh_cn`）：只有恢复数值，例如
`10000-10003` 食草食物 +10/+20/+40/+100 饱食 & +3/+6/+15/+40 好感、
`10060` 酒神佳酿 +100 好感、`10090` 仙宠泉水 +100 寿命。

## 6. 踩过的坑（别再踩）

1. **客户端技能书数据有 12 行完全重复**（`10600-10605`/`10610-10615`）；按行数统计会得到 402 而不是 390。
2. **种族限制有两种文案**：`仅X可学` 与 `X的特有技能`（家族 421-427）。只匹配前者会漏 7 个家族。
3. **effect 34 一族两义**（固定回血 vs 吸血百分比），不能只按 effect 号定尺度。
4. **`10237` 会重置客户端选宠**（表现为召回宠物）。拒绝路径、合体过渡都不要发。
5. **现有两个宠物定时器都会自行停止**：合体会取消"补能定时器"，能量归零会结束"消耗定时器"。
   **照护计时不能挂在它们身上**（本轮已改成专用定时器）。
6. **登录时的"出战"走的是同一个 CallOut 命令**，不能用"是不是登录"区分；
   要么按 identity（`ServerSessionLifecycle` vs `SecureClient`），要么就把刷新放到**包处理函数**里。
7. **百分比通道是万分比**：`physical_damage_bonus`、`ignore_physical_defense`、
   `critical_damage_percent`、`damage_rebound` 都要 ×10000；`life_absorption`（bp）与
   `life_absorption_flat`（固定值）是两个不同通道。
8. **部署 = 踢人下线**：`docker compose --profile legacy-raw up -d --build server`
   会重建容器、清空容器日志。**部署前先 `docker logs godswar-server > artifacts/xxx.log`**。
9. 本仓库**不是 git 仓库**（没有 `.git`），改动没有版本兜底，动数据前先备份。

## 9. 硬规则（沿用本仓库约定）

1. 规则只能来自**客户端原文**或**实测/查库**；两者都取不到就写"未知"，**不许编偏移、编数值**。
2. 结论分开标注：`【原文】/【实测】/【推断·未证实】`。
3. 所有游戏状态变更必须落库（事务）；内存对象只用于投影给客户端。
4. 只做被要求的那一件事；不顺手改无关文件。
5. 条件允许可以用夹具验证
6. **查日志/查库之前不许下"成功"结论**；库里数值变了不等于那件事成功，必须找到对应那一行。
7. 不许改动用户既有游戏数据；需要夹具先问。手改数据时**不要动 `inventory_revision`**。
8. 部署/重启 = 踢人下线，**必须先经用户同意**；用户说"回滚"时只回滚被明确指定的东西。
