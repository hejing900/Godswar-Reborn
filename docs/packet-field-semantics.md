# 字段含义字典

本文件回答：**每个字段代表游戏里的什么**。

与 `packet-structures-reference.md` 的分工：那里写「偏移 + 类型 + 字段名」（是什么字节），
这里写「这个值的语义、取值范围、客户端拿它干什么」（代表什么）。

所有结论来自 `src/Godswar.Server/` 源码中已核对过的编码逻辑。凡源码未确认的，标为「未确认」。

---

## 1. 通用字段语义

### 1.1 帧头两字段

| 字段 | 语义 |
| --- | --- |
| +0 `u16` | **整帧字节数**，含这 4 字节头。客户端按它切包 |
| +2 `u16` | opcode。**同一个数字在不同方向/长度下含义不同**（见 §8） |

### 1.2 对象 ID（`u32`）

不是随意编号，客户端**按数值区间决定把对象当成什么**：

| 区间 | 客户端认为它是 |
| --- | --- |
| `0 .. 1499` | 玩家 |
| `1500 .. 7999` | NPC |
| `8000 .. 49999` | 怪物 |

`0x1448`（十进制 5192）是**本机玩家的固定本地 ID**，属于玩家区间。
服务端给旁观者广播时必须换成真实世界对象 ID，否则旁观者会把「这个玩家」
错认成 NPC 或怪物。

> 真实教训：Arena NPC 曾用 `57001..57005`，超出 NPC 区间，客户端从未走 NPC 创建路径。
> 重新编号到 `5701..5705` 才渲染出来。

### 1.3 视觉压缩字节 `(grade << 4) | quality`

很多包用**一个字节塞两个值**：

| 位 | 含义 | 原生上限 |
| --- | --- | --- |
| 高 4 位 | 品阶 grade | 12 |
| 低 4 位 | 品质 quality | 13 |

超上限时 nibble 会截断，所以仓库在原生体之后追加版本化 `GWX1` 尾部承载全字节 Q20/G25。
**未扩展的包仍走原生解码器**，两者并存。

### 1.4 能力值百分比 = 万分之一定点

需要小数的百分比字段用 `f32`，值是 **`整数百分比 × 10000` 的倒数**：

```
线上值 = 服务端整数值 / 10000
```

例如 `PhysicalDamageBonus` 存 `15000` → 线上 `1.5`。

### 1.5 经验值：signed-16 截断问题

经验字段是 `i32`，但**富客户端只按有符号 16 位读**某些位置。
因此存在专用编码器 `WriteLegacyFighterExperience`，把超范围值安全截断，
避免显示成负数。凡经验字段都走它，不要直接写。

### 1.6 坐标

坐标一律 `f32`，三个分量含义是 **X / Y(高度) / Z(地面)**。
注意仓库里有两种排列写法：

- `PlayerWorldSpawn`：+60 X、+64 Z、+68 地形高（Y 放最后）
- `PhysicalDamage`：+8 X、+12 Y、+16 Z（顺序排列）

**不要假设三轴顺序一致**，按每个包各自的定义读。

### 1.7 朝向 / 角度

`f32` 弧度或角度（客户端自行解释），出现在怪物移动包 +40 与 +28。
仓库只透传，不做换算。

## 2. 玩家状态字段语义

来源：`PacketBuilder.Utilities.cs` 的 `PatchReferencePlayerPacket`。
`PlayerDetail` 与 `PlayerStatusUpdate` **共享同一套布局**，`fieldBase` = 名字字段之后。

以下偏移都是**相对 `fieldBase`**：

| 偏移 | 类型 | 语义 |
| ---: | --- | --- |
| +0 | `u8` | 性别 |
| +4 | `f32` | 位置 X |
| +8 | `f32` | 位置 Y（此布局固定写 0） |
| +12 | `f32` | 位置 Z |
| +16 | `f32` | 固定 1.0 |
| +52 | `i32` | 职业 |
| +56 | `i32` | 当前经验（走 legacy 编码器） |
| +60 | `i32` | 等级 |
| +64 | `i32` | 当前 HP |
| +68 | `i32` | 当前 MP |
| +104 | `i32` | 最大 HP |
| +108 | `i32` | 最大 MP |
| +112 | `i32` | HP 回复总量 |
| +116 | `i32` | MP 回复总量 |
| +120 | `i32` | 物理攻击 |
| +124 | `i32` | 物理防御 |
| +128 | `i32` | 魔法攻击 |
| +132 | `i32` | 魔法防御 |
| +136 | `i32` | 命中 |
| +140 | `i32` | 闪避 |
| +144 | `i32` | 暴击 |
| +148 | `i32` | 暴击抗性 |
| +152 | `f32` | 物理伤害加成（万分之一） |
| +156 | `f32` | 魔法伤害加成（万分之一） |
| +160 | `i32` | 伤害吸收 |
| +164 | `f32` | 受到治疗加成 `AcceptCure`（万分之一） |
| +168 | `f32` | 输出治疗加成 `Cure`（万分之一） |

**易错点**：

- 名字后面紧跟着**性别**（1 字节），不是立即跟坐标。
- +8 的 Y 在这套布局里**固定写 0**，不要塞真实高度。
- 治疗有两个字段，**方向相反**：`AcceptCure` 是「我受到的」，`Cure` 是「我造成的」。
  客户端 PersonalInfoUI 的 Healing 显示读的是**后者**。
- 不要泄漏模板玩家位置：捕获模板里带着固定坐标，发布远程状态包时必须覆盖，
  否则远程玩家会显示在模板玩家的位置上。

## 3. 职业 / 阵营 / 性别

| 字段 | 类型 | 语义 |
| --- | --- | --- |
| 职业 | `u8` | 直接使用**数据库职业 ID**，不做映射。0=战士 1=冠军 2=法师 3=牧师 |
| 阵营 | `u8` | 0 = 斯巴达，1 = 雅典 |
| 性别 | `u8` | 原始值。**注意 +1 的情况见下** |
| 脸型 | `u8` | 外观索引 |
| 发型 | `u8` | 外观索引 |

### 职业的两套字节（重要）

源码里同时存在 `ToWorldProfessionByte` 和 `ToClientProfessionByte`，两者**当前都是恒等函数**，
但注释明确警告：

- **世界出场包**（`0x2725`）的 +58 用「世界」职业字节
- **UI / 明细包**的 +52 用「客户端」职业字节
- 静态方法 `ToWorldProfessionByte` 注释：*世界出场字节与 DB class id 一致*
- `ToClientProfessionByte` 注释：*世界出场的视觉用的是另一套 avatar 顺序*

所以这两个字段**语义独立**，即便此刻取值相同也不要合并。

### 性别字段的陷阱

| 包 | 偏移 | 语义 |
| --- | --- | --- |
| `0x2725` 世界出场 | +52 | **原始性别** 0/1 |
| `0x27D9` 装备外观刷新 | +12 | **性别 + 1**（1/2） |

`0x27D9` 的注释明确写着：捕获包在 +12 放的是 **性别 + 1**，不是发型、也不是职业。
把这两个包当成同构是常见错误。

`ClientStatusEffect(StatusId, RemainingSeconds)`，剩余时间是**无符号 32 位秒**。

来源：`ExperienceBoostContracts` / `ExperienceBoostState`。

| 580 | 天赋经验 +50% |
| 581 | 天赋经验 +100% |
| 582 | 天赋经验 +200% |
| 583 | 天赋经验 +300% |
| 584 | 天赋经验 +400% |
| 586 | 最大经验药水 |
| 587 | 天赋药水 +50% |
| 588 | 超级天赋药水 +200% |
| 589 | 不可思议天赋药水 +300% |
| 590 | 最大天赋药水 +400% |
| 1007 | 公会双倍经验 16 小时 |
| **1500** | Kijin  patron |
| **1501** | Oni patron |
| **1502** | Demon Lord Seed |
| **1503** | 真·Demon Lord |

### 4.3 加成「种类」码（不是 StatusId）

`ExperienceBoostKinds`，用于区分加成通道：

| Kind | 含义 | 影响战士经验 |
| ---: | --- | --- |
| 14 | 消耗品 | 是 |
| 20 | 天赋 | **否** |
| 22 | 周末 | 是 |
| 23 | Trick or Treat | 是 |
| 24 | 宠物 | **否** |
| 100 | 公会 | 是 |
| 101 | 公会天赋 | **否** |
| 1008 | 捐赠者 | 是 |
| 1009 | 阵营区域 | 是 |
| 1010 | 战斗通行证 | 是 |

**注意**：20 / 24 / 101 明确不影响战士经验（它们走天赋或宠物通道）。
把这三者当成通用经验加成是错的。

## 5. 物品记录字段语义

### 5.1 属性槽

每条物品记录有 **5 个普通属性槽**（偏移 4/8/12/16/20），各 `i32`：

| 值 | 语义 |
| --- | --- |
| `>= 0` | 属性 ID，存在 |
| `-1` | **空**（哨兵） |

> 紧凑存储里用 `null` 表示空，捕获记录里用 `-1`。
> 转换时 `null` ↔ `-1`，不要把 `-1` 当有效属性 ID。

### 5.2 品质 / 品阶 / 绑定 / 堆叠

| 偏移 | 字段 | 语义 |
| ---: | --- | --- |
| 24 | 品质 Q | 1..20（原生上限更低，见 §1.3） |
| 25 | 品阶 G | 1..25 |
| 26 | 绑定 | 绑定类型 |
| 27 | 堆叠 | 当前堆叠数 |

### 5.3 空槽的完整编码

不能只清零。空槽必须写成：

```
偏移 0..20 全部 = -1   （5 个属性槽都标记为空）
[24] = 1  品质
[25] = 1  品阶
[26] = 0  绑定
[27] = 1  堆叠
```

### 5.4 视觉字节里的两个值

装备视觉标志每槽一个字节 = `(grade << 4) | quality`。

## 6. 战斗字段语义

### 6.1 技能施放 `10040`

| 偏移 | 语义 |
| ---: | --- |
| +4 | 施法者 ID |
| +8 | 技能 ID |
| +16 | 目标 ID |
| +20 | **施法状态**：客户端发 0，服务端转发放 **10** |

`10` 是「已开始表演」的状态码。原样回写客户端包时不改这个值，
旁观者就不会播技能动作。

### 6.2 技能伤害 `10045` / `0x273D`，32 字节

| 偏移 | 语义 |
| ---: | --- |
| +4 | 攻击者 ID |
| +8 | 目标 ID |
| +12 | **结果标志**（低位决定伤害/治疗等语义） |
| +16 | 伤害量 |
| +20 | 技能 ID |
| +24 / +28 | 目标 X / Z |

### 6.3 治疗复用同一个包

治疗**不另开 opcode**，而是复用 `10045` 并改两个字段：

| 字段 | 治疗时的值 |
| --- | --- |
| +12 结果标志 | `0x101` |
| +16 伤害量 | 治疗量经专用编码（见下） |

### 6.4 群体伤害 `10047` / `0x273F`

- 头部 **17** 字节
- 之后每条命中 **12** 字节
- +4 攻击者、+8 命中数、+12 技能 ID、**+16 聚合状态命中标志**

每条命中：

| 命中内偏移 | 语义 |
| ---: | --- |
| +0 | 目标 ID |
| +4 | 攻击类型 `u8` |
| +5 | 伤害类型 `u8` |
| +6 / +7 | 对齐填充，固定 0 |
| +8 | 伤害 |

> +16 的聚合状态标志**当前恒为 0**，因为状态施加尚未建模。
> 保留字段以维持捕获布局。

### 6.5 物理伤害 `10026` / `0x272A`

长度二选一：**30 字节**（普通）或 **32 字节**（含怪物动画标志）。

| 偏移 | 语义 |
| ---: | --- |
| +4 | 攻击者 ID |
| +8 / +12 / +16 | 攻击者 X / Y / Z |
| +20 | 目标 ID |
| +24 | 伤害 |
| +28 | **结果** `u8` |
| +29 | **伤害类型** `u8`（默认 1） |
| +30 | **动画标志**（仅 32 字节版本） |

**+30 的语义**：怪物攻击时客户端读它决定是否播放模型动画。
捕获到的 32 字节攻击包**明确把它留 0**——所以「长度 32」不等于「要播动画」。

### 6.6 玩家死亡 `10018` / `0x2722`，28 字节

| 偏移 | 语义 |
| ---: | --- |
| +4 | 玩家 ID |
| +8 / +12 / +16 | 死亡位置 X / Y / Z |
| +20 | 地图 ID |
| +24 | 固定 1 |

**注意 opcode 复用**：`10018` 也用于场景切换（24 字节）。
区分方式是**长度 + 对象身份**：本机玩家 = 切场景，其他对象 = 死亡通知。

### 6.7 经验获得 `10031` / `0x272F`，13 字节

| 偏移 | 语义 |
| ---: | --- |
| +4 | 本次获得经验 |
| +8 | 当前总经验 |
| +12 | 结果 `u8` |

**关键**：客户端只读 **+4** 来弹「获得经验」提示。
早期捕获里 +4 和 +8 恰好相等，掩盖了这个事实——如果把 +8 当显示源，
提示会显示成总经验。

### 6.8 怪物死亡奖励 `10027` / `0x272B`，116 字节

| 偏移 | 语义 |
| ---: | --- |
| +4 | 怪物 ID |
| +8, +12, +16, +20, +24 | **5 个组队槽位**；第 0 位是玩家，其余填 `-1` |
| +48 | 当前经验（legacy 编码） |
| +68 | 当前天赋经验 |
| +88 | 当前天赋点 |
| +108 | 怪物 ID（再次出现） |

> 5 个槽位是固定长度；未使用的槽填 `-1`（`0xFFFFFFFF`）而不是 0。

### 6.9 施法打断 `10171`，8 字节

+4 = 施法者 ID，**在接收者的 ID 命名空间里**。
自收是 `0x1448`，旁观者收的是施法者的世界 ID。
客户端显示 `Skill09`（技能被打断）。

## 7. 怪物字段语义

### 7.1 怪物外观/刷怪包

| 偏移 | 语义 |
| ---: | --- |
| +20 | 当前 HP |
| +24 | 最大 HP |
| +28 | X |
| +36 | Z |
| +40 | 朝向 |

> 注意 +28 到 +36 之间**跳过了 +32**，不是连续的 X/Y/Z。

### 7.2 怪物创建 `10020`

+4 是**打包值**：

| 位 | 含义 |
| --- | --- |
| 高 16 位 | **地图 ID** |
| 低 16 位 | NPC/怪物外观类型标志 |

写法：`(mapId << 16) | (appearance & 0xFFFF)`。

标准 Arena NPC 的正确值是 `0x00390011`（内存里 `11 00 39 00`），
**不是** `0x00000011`。

客户端处理器（`Origin.exe` VA `0x004EBC80`）比较**高 16 位与玩家当前地图**，
不匹配就丢弃、不创建对象。

### 7.3 怪物移动开始 `10016` / `0x2720`，40 字节

| 偏移 | 语义 |
| ---: | --- |
| +4 | 怪物 ID |
| +8 | **恒为 0**（所有捕获的游荡包都是 0） |
| +12 | 移动模式，`1` |
| +16 / +20 / +24 | 位置 X / Y / Z |
| +28 / +32 / +36 | 速度分量 X / Y / Z |

### 7.4 怪物移动结束 `10017` / `0x2721`，34 字节

| 偏移 | 语义 |
| ---: | --- |
| +4 | 怪物 ID |
| +8 | 恒为 0 |
| +12 | tick 计数 |
| +16 / +20 / +24 | 位置 X / Y / Z |
| +28 | 朝向 |
| +32 | 尾部 `u16`，捕获中为 0 |

### 7.5 怪物生命周期标记 `10023` / `0x2727`，8 字节

+4 = 怪物 ID。

> **坑**：`10023` 在 `Opcodes.cs` 里叫 `Storage`，但它同时也是怪物生命周期标记。
> 捕获到的 8 字节 `10023` 帧**不是仓库数据**。仓库用的是 `10034`。

## 8. opcode 复用对照（按长度/上下文消歧）

| opcode | 形态 A | 形态 B | 如何区分 |
| ---: | --- | --- | --- |
| 10018 | 场景切换 24 字节 | 玩家死亡 28 字节 | 长度 + 对象是否本机 |
| 10019 | 服务端 EnterMain | 客户端复活（历史） | 方向 |
| 10082 | C2S 请求 648 字节 | S2C 应答 648 字节 | **同长度，只能靠方向** |
| 10084 | C2S 交付 16 字节 | S2C 应答 12 字节 | 长度 |
| 10040 | C2S 施放 | S2C 视觉 | 方向 |
| 10109 | C2S 开始 | S2C 结果 | 方向 |
| 10171 | C2S 上报 | S2C 通知 | 方向 |
| 10200 | 明细请求/应答 | 时装复选框载体 | 最后一个 DWORD |
| 10202 | 状态更新 | 明细 ACK | 长度 |
| 10023 | 仓库（命名） | 怪物标记（实际） | 长度 8 = 怪物标记 |
| 10026 | C2S 普攻 | S2C 物理伤害 | 方向 |
| 10192 | 移动或加载 | — | 未细分 |

`10082` 是最危险的一个：**两个方向长度完全相同**，只能靠方向区分。

## 9. 抓包与改包时的字段检查清单

1. 对象 ID 是否落在正确区间（玩家 < 1500 / NPC 1500-7999 / 怪物 8000-49999）
2. 发给旁观者时，+4 与 +16 的身份是否都已从本机 ID 换成世界 ID
3. 视觉字节有没有被 nibble 截断（G>12、Q>13）
4. 空物品槽是否写了完整的 `-1 + 1/1/0/1`
5. 经验字段是否走了 legacy 编码器
6. 百分比字段是否按万分之一换算
7. `0x2725` 的 +0xB0 是否等于收包者当前地图
8. `10020` 的 +4 是否写成 `(mapId<<16) | appearance`
9. `0x27D9` 的 +12 是否写了**性别 + 1**
10. 治疗是否用了 `0x101` 结果标志
11. 组队奖励未使用槽是否填 `-1` 而非 0
12. 三个坐标的顺序是否按该包自己的定义（不统一）

## 10. 未确认项（不要凭推测填）

以下语义在源码中**没有**被确认，改动前需要新的捕获证据：

- `10045` +12 结果标志的**完整位定义**（只知道 `0x101` = 治疗）
