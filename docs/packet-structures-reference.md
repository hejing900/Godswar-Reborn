# 数据包结构参考（客户端 ↔ 服务端）

本文件回答三个问题：

1. **客户端各功能发包长什么样**（C2S）
2. **服务端发包长什么样**（S2C）
3. **客户端期望收到什么包**（客户端解码器的硬性要求）

信息的权威来源是 `src/Godswar.Server/Protocol/Opcodes.cs` 的注释（记录捕获日期与偏移）、
`src/Godswar.Server/Packets/PacketBuilder.*.cs`（服务端编码器），以及
`tests/Godswar.Server.ProtocolChecks`（黄金字节回归）。

> 标注约定：本文只写已在源码或捕获证据中确认的偏移。未确认的字段标为「保留」，
> 不做推测。`Opcodes.cs` 中的中文/英文原注释是最原始的证据，改包前应回查。

## 1. 共同框架

### 1.1 帧格式

所有包都是 **4 字节头 + 载荷**，小端：

| 偏移 | 类型 | 含义 |
| ---: | --- | --- |
| 0 | `u16` | **整帧长度**（含这 4 字节头）。不是载荷长度 |
| 2 | `u16` | opcode |
| 4 | — | 载荷开始。本文所有「+N」都**从帧首**计数，所以 +4 就是第一个载荷字 |

对应实现：`Protocol/GamePacket.cs`（读取）、`Packets/PacketBuilder.Utilities.cs`（写入）。

### 1.2 加密

载荷在线上被一个 **256 字节循环 XOR 表** 混淆，两个方向各维护独立的指针：

```
byte[i] = byte[i] ^ HashOne[p] ^ HashTwo[p]
p = (p + 1) & 0xFF
```

- 两张表是 `Packets/ReferencePackets.Generated.cs` 里的 `HashOne` / `HashTwo`。
- 指针按**字节**递增，跨包连续，不按包重置。
- 收发方向指针独立：抓包时必须为 C2S 和 S2C 各维护一个 cipher 实例。
  这正是 `tools/Godswar.CaptureProxy/Program.cs` 里
  `clientToServerCipher` / `serverToClientCipher` 分开的原因。

实现：`Protocol/PacketCipher.cs`。

### 1.3 对象 ID 命名空间（最容易踩的坑）

`Origin.exe` 在 VA `0x004696A0` 处按数值区间给世界对象分类：

| ID 区间 | 类别 |
| --- | --- |
| `< 1500` | 远程玩家 |
| `1500..7999` | NPC |
| `8000..49999` | 普通怪物 |

推论：

- **同一个对象在服务端和不同客户端上的 ID 不同**。客户端本地玩家固定用
  `0x1448`（5192）；服务端广播给旁观者时必须翻译成世界对象 ID。
  例：`PacketBuilder.SkillCastVisual` 把客户端包 +4 的 ID 换成服务端世界 ID，
  `SelfTargetSkillCastVisual` 连 +16 的目标 ID 也要换。
- **超出区间的 ID 永远不会走原生创建路径**。历史 Arena NPC 用 `57001..57005`
  就因此没被当作 NPC 渲染，后来重新编号成 `5701..5705` 才生效。

### 1.4 十进制的 `Opcodes.cs` 与十六进制的 `PacketBuilder`

两套写法指的是同一个 opcode，换算时必须小心：

| `PacketBuilder` 常量 | 值 | 十进制 | 含义 |
| --- | ---: | ---: | --- |
| `EnterMainOpcode` | `0x2723` | 10019 | 进入主场景 |
| `PlayerWorldSpawnOpcode` | `0x2725` | 10021 | 玩家世界出场 |
| `KitBagDetailOpcode` | `0x2731` | 10033 | 背包明细 |
| `NpcDialogOpenOpcode` | `0x2753` | 10067 | NPC 对话打开 |
| `NpcFunctionActionResponseOpcode` | `0x2756` | 10070 | NPC 功能应答 |
| `PhysicalDamageOpcode` | `0x272A` | 10026 | 物理伤害 |
| `PlayerDeathOpcode` | `0x2722` | 10018 | 玩家死亡（与场景切换同号） |
| `SkillDamageOpcode` | `0x273D` | 10045 | 技能伤害 |
| `SkillCastImpactOpcode` | `0x273E` | 10046 | 技能命中 |
| `BagItemActionOpcode` | `0x2748` | 10056 | 背包物品操作 |
| `AfterLoginOpcode` | `0x2876` | 10358 | 登录后清单 |
| `FashionEffectVisibilityOpcode` | `0x27DA` | 10202 | 时装可见性 |
| `PlayerDetailAckOpcode` | `0x27DA` | 10202 | 与上行同号复用 |

**opcode 会被复用**，方向甚至语义都不同。判断含义必须同时看 opcode + 长度 + 上下文。

## 2. 登录与角色选择

流程：`Login(1)` → `ServerList(3)` → `SelectServer(4)` → `SendServer(7)` →
重定向到游戏端口 → `LoginGameServer(10000)` → `RoleInfo(10002)`。

### 2.1 [C2S] `Login = 1` — 账号登录，68 字节

| 偏移 | 类型 | 含义 |
| ---: | --- | --- |
| 0 | `u16` | 68 |
| 2 | `u16` | 1 |
| 4 | ASCII×32 | 用户名，定长空补 |
| 36 | ASCII×32 | 密码 |

证据：`tools/Godswar.Server.LegacyLoginProbe/ProbePackets.cs`。

### 2.2 [C2S] `SelectServer = 4` — 选服，44 字节

| 偏移 | 类型 | 含义 |
| ---: | --- | --- |
| 0 | `u16` | 44 |
| 2 | `u16` | 4 |
| 36 | `u8` | 大区（realm）编号 |

### 2.3 [S2C] `ServerList = 3` — 大区列表

头部 6 字节，之后每个大区记录 **48 字节**：

| 偏移 | 类型 | 含义 |
| ---: | --- | --- |
| 0 | `u16` | 6（头部长度） |
| 2 | `u16` | 3 |
| 4 | `u16` | **登录结果状态，不是大区数量**。1 = 成功，2 = `AccountUnuse` |

记录内（相对记录起点）：

| 记录偏移 | 类型 | 含义 |
| ---: | --- | --- |
| 0 | `u16` | 48（本记录长度） |
| 2 | `u16` | `GameServerInfo = 10008` |
| 4 | ASCII×36 | 大区名 |
| 40 | `u8` | 大区线号 |
| 41 | `u8` | 是否推荐（1/0） |
| 42..45 | — | 捕获兼容后缀 |
| 46 | `u8` | **结束标记**：非 0 时客户端才收尾列表，仅最后一条置 1 |

### 2.4 [S2C] `SendServer = 7` — 选定大区回执

沿用捕获模板，改写两处：

| 偏移 | 长度 | 含义 |
| ---: | ---: | --- |
| 36 | 36 | 大区名 |
| 72 | `u8` | 大区线号 |

### 2.5 [S2C] 游戏服重定向

沿用 `ReferencePackets.NewGameServerTemplate`，改写：

| 偏移 | 类型 | 含义 |
| ---: | --- | --- |
| 5 | ASCII×23 | 目标主机 |
| 40 | `i32` | 目标端口 |
| 45 | ASCII×25 | 大区标识串 |

> 抓包代理正是拦截这个包，把主机改写为 `--local-advertised-host`
> （默认 `127.1.1.110`）和本地游戏端口，从而把客户端引到代理上。

### 2.6 [C2S] `LoginGameServer = 10000` — 连游戏服，62 字节

| 偏移 | 类型 | 含义 |
| ---: | --- | --- |
| 4 | ASCII×32 | 用户名 |
| 36 | ASCII×25 | 大区标识串 |
| 61 | `u8` | 大区线号 |

### 2.7 [S2C] `AfterLogin = 0x2876 / 10358` — 登录后清单

固定 **44 字节/条**，连续多条（与 `AfterLoginManifest` 记录一一对应）：

| 偏移 | 类型 | 含义 |
| ---: | --- | --- |
| 0 | `u16` | 44 |
| 2 | `u16` | 10358 |
| 4 | `i32` | 记录 ID |
| 8 | ASCII×32 | 哈希串 |
| 40 | `u8` | 0 |
| 41 | ASCII | `'8'` |
| 42 | ASCII | `'8'` |
| 43 | `u8` | 0 |

> 这是原生登录生命周期的一部分，**不是通用游戏数据引导**。清单必须与
> 可用服务端逐条对齐。

### 2.8 [S2C] 登录失败

7 字节，硬编码：

```
06 00 <reason u16 LE> 00 00 F0
```

即长度 6、opcode = `reason`、尾字节 `0xF0`。

### 2.9 [S2C] 建号 / 删号成功

固定 12 字节（`0x27B4 = 10164`）：

- 建号：`0C 00 B4 27 13 27 8D 0B 01 00 00 00`
- 删号：`0C 00 B4 27 14 27 A4 75 08 00 00 00`

## 3. 进入世界

### 3.1 [S2C] `SceneChange = 10018` — 场景切换，24 字节

`10018` 被**按对象身份重载**：本机玩家是切场景，其他对象是死亡通知。

| 偏移 | 类型 | 含义 |
| ---: | --- | --- |
| 0 | `u16` | 24 |
| 2 | `u16` | 10018 |
| 4 | `u32` | **本机玩家对象 ID** |
| 8 / 12 / 16 | `f32` | 目的地 X / Y / Z |
| 20 | `u16` | 保留，0 |
| 22 | `u16` | 目的地图 ID |

发送后客户端会回 `10007` 与 `10200`（顺序任一），服务端对 `10200` 回玩家明细。

> 客户端解码器要求：+4 必须等于本机玩家对象 ID，否则不会当作切场景。

### 3.2 [C2S] `ClientReady = 10007` — 客户端就绪，34 字节

### 3.3 [C2S] `PlayerDetailRequest = 10200` — 明细请求，12 字节

| 偏移 | 类型 | 含义 |
| ---: | --- | --- |
| 4 | `u32` | 0 |
| 8 | `u32` | 1 |

> `10200` 同样是重载包：它还承载 Fashion Show 复选框（在最后一个 DWORD）。

### 3.4 [C2S] `Walk = 10194` — 移动，20 字节（心跳噪声）

| 偏移 | 类型 | 含义 |
| ---: | --- | --- |
| 4 | `u32` | 移动状态：**低 16 位是对象 ID，高 16 位是状态** |

服务端广播给旁观者时保留高 16 位、替换低 16 位为自己的世界 ID：

```
serverState = (clientState & 0xFFFF0000) | (worldObjectId & 0xFFFF)
```

### 3.5 [S2C] `PlayerWorldSpawn = 0x2725 / 10021` — 玩家世界出场

字段级（已确认部分）：

| 偏移 | 类型 | 含义 |
| ---: | --- | --- |
| 0 / 2 | `u16` | 长度 / 10021 |
| 4 | `u32` | 世界对象 ID |
| 8 | `u32` | 角色数据库 ID |
| 12 | ASCII×32 | 角色名 |
| 44 | `i32` | 当前 HP |
| 48 | `i32` | 最大 HP |
| 52 | `u8` | 性别 |
| 53 | `u8` | 阵营 |
| 54 | `u16` | 等级 |
| 56 | `u8` | 脸型 |
| 58 | `u8` | 职业（世界字节） |
| 59 | `u8` | 发型 |
| 60 / 64 / 68 | `f32` | 坐标 X / Z / 地形高 |
| 72 | `f32` | 1.0 |
| 0x50 | `u8` | PK 模式 |
| 81 | 18 字节 | 视觉标志，每槽 `(grade << 4) \| quality` |
| 102 | 17 字节 | 每槽属性个数 |
| 124 | 18×`u16` | 每槽装备 ID |
| 168 | `u32` | 装备掩码，按槽位 `1 << slot` |
| 178 | `u16` | 状态数量 |
| 180 | — | 状态 ID 数组，每项 `u32` |
| 0xB0 | `u16` | **地图 ID** |

**客户端解码器硬性要求**：+0xB0 的地图必须等于收包者当前地图，否则整个包被丢弃、
该玩家不出现。

**视觉扩展**：原生 Q/G 只用 nibble（grade 上限 12、quality 上限 13）。仓库在
nibble 之后追加版本化 `GWX1` 全字节尾部承载 Q20/G25；未扩展的 260 字节包仍走原解码器。

### 3.6 [S2C] `0x27D9` — 装备外观刷新，64 字节

| 偏移 | 类型 | 含义 |
| ---: | --- | --- |
| 4 | `u32` | 对象 ID |
| 8 | `u32` | 发型 |
| 12 | `u32` | **性别 + 1**（不是发型，也不是职业） |
| 16 + slot×4 | `u32` | 各槽装备 ID |

> 时装分支下，索引 10/11（手持武器与盾）**仍用权威装备**，只让时装定义拥有身体部位。

### 3.7 [S2C] `0x27D2` — 玩家位置，20 字节

| 偏移 | 类型 | 含义 |
| ---: | --- | --- |
| 4 | `u32` | `0x00020000 \| (对象ID & 0xFFFF)` |
| 8 / 12 | `f32` | X / Z |
| 16 | `f32` | 1.0 |

### 3.8 [S2C] `0x27D7` — 玩家称号，80 字节

| 偏移 | 类型 | 含义 |
| ---: | --- | --- |
| 4 | `u32` | 对象 ID |
| 8..71 | 64 字节 | **不是称号文本**，是公会/军团类辅助字段 |
| 72..75 | — | 不透明 |
| 76 | `u32` | 已选称号 ID |

### 3.9 [S2C] `0x2808` — 宠物世界存在，108 字节

| 偏移 | 类型 | 含义 |
| ---: | --- | --- |
| 4 | `u32` | 宠物 ID |
| 8 | `u32` | 主人对象 ID |
| 64 | `u8` | 1 |

> 宠物 ID 为 0 时原生处理器**忽略该包**，远程玩家不会显示宠物。

### 3.10 [S2C] `WorldObjectRemove = 0x2728 / 10024` — 移除世界对象

| 偏移 | 类型 | 含义 |
| ---: | --- | --- |
| 4 | `u32` | 对象数量 N |
| 8 + i×4 | `u32` | 第 i 个对象 ID |

### 3.11 [S2C] NPC 创建 `10020`

| 偏移 | 类型 | 含义 |
| ---: | --- | --- |
| 4 | `u32` | **打包值**：低 16 位 = NPC 外观标志，高 16 位 = 地图 ID |

必须写成 `(mapId << 16) | (appearance & 0xFFFF)`。标准 Arena NPC 是
`0x00390011`（`11 00 39 00`），**不是** `0x00000011`。

客户端处理器（VA `0x004EBC80`）会比较高 16 位与玩家当前地图，不匹配就丢弃。

### 4.1 [C2S] `BasicAttack = 10026` — 普通攻击

### 4.2 [C2S] `SkillCast = 10040` — 技能施放

| 偏移 | 类型 | 含义 |
| ---: | --- | --- |
| 4 | `u32` | 施法者对象 ID（客户端填本机 ID） |
| 8 | `u32` | 技能 ID |
| 16 | `u32` | 目标对象 ID |
| 20 | `u32` | 施法状态：客户端发 0，服务端转发放 **10** |

40 字节形态额外带坐标：

| 偏移 | 类型 | 含义 |
| ---: | --- | --- |
| 24 / 28 | `f32` | 施法者 X / Z |
| 32 / 36 | `f32` | 目标 X / Z |

### 4.3 [S2C] 技能视觉 `0x2738 / 10040`（与 C2S 同号）

服务端把客户端包**原样回写并改写身份**：

- +4 施法者 → 世界对象 ID
- +16 目标 → 世界对象 ID（自施法时两者都指向施法者）
- +20 状态 → 10

怪物施法由服务端从零构造，40 字节，字段同上。

## 5. 物品与背包

### 5.1 物品记录格式

**进入游戏记录（92/72 字节）**：

| 偏移 | 类型 | 含义 |
| ---: | --- | --- |
| 0 | `u32` | 物品 ID |
| 4 / 8 / 12 / 16 / 20 | `i32` | 属性 1..5，`-1` = 无 |
| 24 | `u8` | 品质 Q |
| 25 | `u8` | 品阶 G |
| 26 | `u8` | 绑定 |
| 27 | `u8` | 堆叠数 |
| 28..67 | — | 扩展区（圣石/圣衣等） |
| 68 | `u32` | `0x42` |

**空槽**：偏移 0..20 全部写 `-1`，`[24]=1`、`[25]=1`、`[26]=0`、`[27]=1`。

### 5.2 背包明细 `0x2731 / 10033`

- 头部 24 字节
- 之后每 **12 条记录**一包，每条 72 字节
- 总长 = `24 + 12 × 72`

背包是 **4 页 × 每页 24 格 = 96 格**。

### 5.3 [C2S] 常用 opcode

| opcode | 名称 | 含义 |
| ---: | --- | --- |
| 10049 | `UseOrEquip` | 使用或装备 |
| 10050 | `MoveItem` | 移动物品 |
| 10051 | `BreakItem` | 装备装备请求（92 字节） |
| 10052 | `StorageItem` | 丢弃到地面（delete 哨兵） |
| 10053 | `Sell` | 出售（已知但未使用） |
| 10060 | `SellItem` | **实际出售**，4 字节：背包页 + 页内下标 |
| 10059 | `WarehouseTransfer` | 仓库转移，双向，20 字节描述符 |
| 10034 | `WarehouseSnapshot` | 仓库快照（**不是 10023**） |

> `10060` 的权威槽位 = `页 × 24 + 页内下标`，不带数量——客户端一次卖掉整叠。
> `10023` 是无关的世界对象标记，捕获到的 8 字节 `10023` 帧不是仓库数据。

### 5.4 [S2C] 检查他人装备 `0x2726 / 10022`

- 头部 8 字节
- 21 条 72 字节记录
- 掩码 `u32`
- 总长 = `8 + 21 × 72 + 4`

相关：`0x2743 / 10051` 装备快照，`0x2772 / 10098` 检查档案（336 字节）。

## 6. NPC、商店与任务

### 6.1 NPC 对话族

| opcode | 方向 | 含义 |
| ---: | --- | --- |
| 10067 | C2S | 打开对话，8 字节，+4 = NPC ID |
| 10068 | C2S | 请求对话页 |
| 10069 | C2S | NPC 功能动作 |
| 10070 | S2C | 功能动作应答 |
| 10071 | S2C | 商店目录 |

## 8. 其他功能

### 8.1 服务器时间 `10311`

14 字节：

| 偏移 | 类型 | 含义 |
| ---: | --- | --- |
| 4 | `i32` | **原生 UTC 偏差** = `-(大区 UTC 偏移秒数)` |
| 8 | `u32` | Unix 秒 |

`Origin.exe` 按「Unix 秒 − 该字段」换算，所以线上值是 **UTC 减本地**（bias），
不是常规的「本地减 UTC」。

### 8.2 生肖 `10297`

- 模块 0、SID 1 → 328 字节强制生肖状态
- 16 格组阵列位于状态 `+48`
- SID 3 = 升级，SID 100 = 技能格激活，SID 101 = 技能格升级
- SID 5 = 能量推送，SID 7 = 累积帧

## 9. 改动数据包时的检查清单

1. **长度字段含 4 字节头**，不是载荷长度。
2. **两个方向各一个 cipher 指针**，跨包连续。
3. **本机 ID `0x1448` ≠ 世界对象 ID**，广播前必须翻译。
4. **对象 ID 必须落在 1.3 的区间内**，否则客户端不创建对象。
5. **`10018` 的 +4 必须是本机玩家 ID**，否则不切场景。
6. **`0x2725` 的 +0xB0 必须等于收包者当前地图**，否则整包丢弃。
7. **`10020` 的 +4 是高 16 位地图 + 低 16 位外观**，不是纯外观。
8. **`10026`/`10027`/`10038` 等数字与 `0x272A` 等十六进制是同一批**，勿重复定义。
9. **同号复用要按长度/上下文消歧**：`10018`、`10019`、`10082`、`10084`、`10200`、`10202`、`10109`。
10. **角色专属快照不可重放**（尤其 `10090`）。
